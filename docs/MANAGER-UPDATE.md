# 管理器稳定版更新

管理器 v1.7.1 发布后，在每台已安装 v1.7.0 的节点上运行 README 的固定版本安装命令。命令下载 `v1.7.1` 标签中的脚本，先核验 SHA256，再启动管理器。已有配置时，它会备份原管理器、更新管理入口并打开菜单。看到菜单后可退出。旧管理器的 `a update` 会从 `main` 下载脚本，迁移请使用上述安装命令。

新版管理器的 `a update`、`a u` 和菜单使用内置的稳定标签和摘要。v1.7.1 的内置锁指向此前验证过的 v1.7.0，安装后默认更新入口会报告没有更高的已锁定版本。README 单独固定 v1.7.1 的摘要，避免脚本需要包含自己的摘要。未来更新可以明确给出经独立核验的更高版本及其 SHA256。

取得较新正式发行标签和可信发布记录后，先独立核对该记录的管理器 SHA256，再运行：

```bash
a update --release "${VERIFIED_RELEASE_TAG}" --sha256 "${VERIFIED_MANAGER_SHA256}"
```

目标必须是高于已安装版本的 `vX.Y.Z` 标签。下载限制为 HTTPS、120 秒和 1 MiB。脚本先比较预期摘要，然后校验发行版本、配置架构、节点协议和队列兼容性，最后才执行语法检查与自检。原子替换之前再次核验待安装文件的摘要。摘要应来自独立验证的发布记录。仓库私有或标签无法匿名访问时，可通过受信渠道取得固定脚本和摘要，按正式安装流程本地核验后再运行。

`a update-rollback` 从同目录的受保护备份恢复上次管理器。管理器及备份要求执行用户所有、单一硬链接、普通文件及无其他用户写权限。管理器路径使用同文件系统的原子替换。断电发生在备份写入与管理器替换之间时，旧管理器仍可能在位且上一份回退备份可能已被替换，当前更新器没有跨文件耐久日志。回退到旧管理器也会恢复旧更新行为。

开发分支交付使用单独的审核流程。在隔离环境中，从固定 Git 提交取得开发脚本，检查源码和独立摘要，再显式运行该文件。稳定更新入口只构造本项目的正式标签路径。
