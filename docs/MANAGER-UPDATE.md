# 管理器稳定版更新

正式安装命令继续从 README 固定的 `v1.7.0` 标签下载，并核验发布时记录的 SHA256。已经安装 **1.7.0 或更早旧管理器**的节点，应通过独立核验摘要的新版安装命令迁移到含本修复的正式版本。旧管理器仍会跟随 `main`，迁移时避免使用旧 `a update`。

含此修复的管理器使用内置的稳定标签和摘要。`a update`、`a u` 和菜单检查这份版本锁。内置锁当前指向已发布的 `v1.7.0`，因此同版本节点会直接返回。维护者可更新该锁，摘要来自核验后的固定发行文件。自动发现未来版本需要预先配置的发布签名信任根，当前没有启用。

取得较新正式发行标签和可信发布记录后，先独立核对该记录的管理器 SHA256，再运行：

```bash
a update --release "${VERIFIED_RELEASE_TAG}" --sha256 "${VERIFIED_MANAGER_SHA256}"
```

目标必须是高于已安装版本的 `vX.Y.Z` 标签。下载限制为 HTTPS、120 秒和 1 MiB。脚本先比较预期摘要，然后校验发行版本、配置架构、节点协议和队列兼容性，最后才执行语法检查与自检。下载页面和下载内容本身都不能为未知摘要建立信任。仓库私有或标签无法匿名访问时，可通过受信渠道取得固定脚本和摘要，按正式安装流程本地核验后再运行。

`a update-rollback` 从同目录的受保护备份恢复上次管理器。管理器及备份要求执行用户所有、单一硬链接、普通文件及无其他用户写权限。管理器路径使用同文件系统的原子替换。断电发生在备份写入与管理器替换之间时，旧管理器仍可能在位且上一份回退备份可能已被替换，当前更新器没有跨文件耐久日志。回退到旧管理器也会恢复旧更新行为。

开发分支交付使用单独的审核流程。在隔离环境中，从固定 Git 提交取得开发脚本，检查源码和独立摘要，再显式运行该文件。稳定更新入口只构造本项目的正式标签路径。
