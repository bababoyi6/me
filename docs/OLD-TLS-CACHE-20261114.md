# 旧核心 TLS 磁盘缓存候选

2026-11-14。基线是固定上游 `ac71d92` 与 `3.5.5+tdh.balanced2.security1`。该候选不修改正式管理器、发行资产或生产配置。

旧 `src/tls_front/cache.rs` 启动时扫描目录并按路径读取任意 `.json` 文件，不限制大小；更新时原位覆盖文件。目录属于专用服务 UID，隔离降低了外部篡改机会，但进程被中断时可能留下不完整文件。已通过的 `security1` RTT、协议和系统回退证据只适用于其固定二进制摘要，不能套用到本候选。

`security2` 在旧 TLS 模拟和快速重试补丁之后增加独立的缓存磁盘补丁：

- 只读取配置域名对应的缓存文件，并检查 JSON 内域名与文件名一致；沿用证书域名匹配和 72 小时启动过期规则。
- Linux 上逐级以 `O_NOFOLLOW` 打开目录，以目录描述符打开普通文件；拒绝符号链接和多重硬链接，读取限制 1 MiB，并核对读取前后的文件元数据。
- 写入先创建同目录 0600 临时文件，写完同步，再以目录描述符原子重命名并同步目录；超限数据不持久化。
- CI Rust 回归覆盖域名白名单、域名不匹配、过期、链接、大小上限、原子替换及临时文件清理。

此候选仍需有界 CI 编译与合成协议检查，再评估是否值得进行延迟和系统级复核。缓存的运行中旧 profile 快速重试、真实 TLS 配置源失效后的恢复、实际客户端和公网表现尚无通过结论。正式核心仍为已发布的 balanced2。
