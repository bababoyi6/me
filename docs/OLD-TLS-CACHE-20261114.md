# 旧核心 TLS 磁盘缓存候选

2026-11-14。基线是固定上游 `ac71d92` 与 `3.5.5+tdh.balanced2.security1`。该候选不修改正式管理器、发行资产或生产配置。

旧 `src/tls_front/cache.rs` 启动时扫描目录并按路径读取任意 `.json` 文件，不限制大小；更新时原位覆盖文件。目录属于专用服务 UID，隔离降低了外部篡改机会，但进程被中断时可能留下不完整文件。已通过的 `security1` RTT、协议和系统回退证据只适用于其固定二进制摘要，不能套用到本候选。

`security2` 在旧 TLS 模拟和快速重试补丁之后增加独立的缓存磁盘补丁：

- 只读取配置域名对应的缓存文件，并检查 JSON 内域名与文件名一致；沿用证书域名匹配和 72 小时启动过期规则。
- Linux 上逐级以 `O_NOFOLLOW` 打开目录，以目录描述符打开普通文件；拒绝符号链接和多重硬链接，读取限制 1 MiB，并核对读取前后的文件元数据。
- 写入先创建同目录 0600 临时文件，写完同步，再以目录描述符原子重命名并同步目录；超限数据不持久化。
- CI Rust 回归覆盖域名白名单、域名不匹配、过期、链接、大小上限、原子替换及临时文件清理。

验证按有界 CI 编译、合成协议、延迟初筛和系统生命周期推进。隔离的私有 TLS 源现已验证默认 profile 在源恢复后自动更新，并在源关闭后从磁盘冷加载。运行中已有非默认 profile 老化时的行为、实际客户端和公网表现尚无通过结论。正式核心仍为已发布的 balanced2。

### 私有 TLS 配置源恢复检查

`old-cache-recovery` 只对上方固定 SHA 的候选运行：隔离的 1 CPU、512 MiB、无 swap 回环命名空间中，核心先在 TLS 源不可达时启动并完成双域合成传输；随后启动临时自签名 OpenSSL TLS 源，等待缺失域的快速重试将两个 profile 从默认值更新并持久化；停源后重启核心，核对 profile 从磁盘恢复、缓存文件权限和摘要不变，再完成双域传输。证书和私钥仅位于 CI runner 的临时 `/tmp`，结束清理，不写入仓库或证据文件。该检查仍使用合成 DC 和用户，不代表公网 TLS 源或真实 Telegram 客户端。

首次 [CI 43689870073](https://github.com/bababoyi6/me/actions/runs/43689870073) 在固定二进制 SHA 校验通过后，被测试资源守卫拦下：systemd 单元名未使用守卫要求的 `tdh-paired-` 前缀，恢复场景没有运行。`a7570df` 仅修正单元名；失败记录保留。

[重跑 CI 43691065834](https://github.com/bababoyi6/me/actions/runs/43691065834) 通过。原始 `recovery.json` 和构建清单的提交与二进制 SHA 一致。`apple.com` 与 `gs.apple.com` 起初都是默认 profile；临时源上线后约 19.90 秒，两域均更新为 `merged` 非默认 profile。缓存文件各为 0600、单硬链接、普通文件，大小约 21 KiB。源关闭后重启，两域仍从未变化的缓存文件恢复；三个阶段合计 12 次双向合成传输摘要校验通过。资源限制为 1 CPU、512 MiB、零 swap，记录的 OOM 与 OOM kill 增量均为零，临时进程已清理。[本地原始证据](../../lab-control/evidence/2026-11-15-old-tls-recovery/README.md)。这证明该固定候选在隔离条件下的默认回退、源恢复和冷加载路径；不扩大为生产发布、真实客户端或长期稳定性批准。
