# 1.6.0 后续实验室验收

1.6.0 已公开发布。此文仅跟踪发布后的系统安装、重启和持续运行验收；不改变已有节点核心，也不代替真实客户端或三台物理 VPS 容量验证。用户当前选择仅做实验室验收。

## 荷兰机阶段：未通过

2026-10-25 的只读资源检查确认荷兰机为 Ubuntu 22.04.5、1 vCPU、约 1 GB 内存、无 Swap。实验继续使用 CPU 60%、原动态内存硬限额和 75% 软节流线，未改动宿主内核、SSH、防火墙或全局路由。

在历史测试盘上创建临时覆盖盘后，真实 systemd 客体成功启动，识别并移除了覆盖盘内已知旧测试安装。公开 1.6.0 命令进入依赖安装阶段，但尚未完成。文件映射客体内存在严格内存限制下产生了大量磁盘读写，控制器在约 482 秒时被主动停止，避免继续消耗唯一测试机。记录不是安装成功，也未证明完整瓶颈成因。

## 有界 CI 三角色系统检查：待运行

`Published full-system acceptance` 工作流先检查 KVM 是否可用，不可用即停止，不退回慢速软件模拟。Ubuntu 最小云镜像须经官方签名清单及摘要核验。一次准备软件包和 generic 内核后封存基础盘，分别创建入口、后端一、后端二覆盖盘。因此属于准备好的 Ubuntu 系统安装检查，不宣称三个出厂镜像各自独立准备。

三个客体各逻辑 1 vCPU / 1 GiB，全部进程共享 CPU 60% 限额；物理内存总硬限额最多 2 GiB、软线 75%、Swap 0，并按 CI 宿主可用资源保留内存。单批运行最多 1500 秒，工作流总上限 35 分钟。宿主监听只绑定回环；不公开测试端口。资源门槛不足、OOM、日志或磁盘超限即停止，不自动重跑。

检查直接执行 README 中公开安装命令，不替换下载边界；核对管理器和 balanced2 摘要、systemd 三角色、真实 WireGuard/HAProxy 路径、真实后端服务停止后的双域名主备切换与恢复。Telegram 操作仅为公开 DH 握手，不涉及账号或真实文件。随后正常关闭并启动三个客体，核对新的启动标识、配置/密钥/核心/单元字节保持和双域名握手恢复。

仅导出固定名称的脱敏 JSON 和阶段名；密钥、加入码、回执、虚拟磁盘和原始交互日志不上传。磁盘只在确认客体停止后清理。所有逻辑节点共享 CI 宿主，结果不能当作低配荷兰机三系统并行承载能力或跨机公网速度。
