# 后端可撤销队列接入（执行前登记）

目标是把上一阶段已测出收益的方案接入单文件管理器，默认关闭，不再重复两端整形的旧八对。入口两条WG共享整机带宽：各分配全部容量会超配，等分又浪费空闲容量；本版明确拒绝入口启用，不伪装成已经解决动态共享预算。

只支持后端tdh-b1/tdh-b2的单隧道。`a queue status`只读；`a queue enable <发送预算Mbps> <已测路径容量Mbps> --maintenance`显式开启，发送预算必须≤路径90%，范围1–900Mbps；`a queue disable --maintenance`撤销。数字无默认值，180/200只是隔离实验参数，不能套到生产1Gbps端口标称带宽。需要先排空后端；没有重启Telemt/HAProxy/WG或更换Secret/链接。

生产实现仅复用HTB/fq_codel，无新守护进程。WG systemd drop-in采用可失败的ExecStartPost/ExecStopPost，队列错误不导致隧道或依赖它的代理停机；不修改WG配置。独立互斥锁避免管理器持锁恢复WG时钩子死锁。配置/事务root0700/0600；应用前记录boot/netns/ifindex、队列基线与指纹。相同策略重复开启不重置队列；自定义队列、过滤器、参数/启动钩子漂移或不安全文件拒绝覆盖。失败恢复与SIGKILL恢复分开处理；撤销先落盘禁止重新启用，避免半次撤销在重启后恢复整形。启用期间更新/回退到不支持此功能的管理器会被拒绝，先撤销即可走原回退路径。卸载在其余破坏性清理前撤销队列。

本轮只补受影响的验证：真实私有WG/实际wg-quick和systemd钩子，重复开启/撤销、自定义配置拒绝、部分应用失败、SIGKILL恢复、WG接口重建、失败钩子保持WG可用、未完成撤销不自动重新启用、权限和密钥不变。使用唯一临时unit和独立netns，正常完成清理；这是服务重启/重建，不宣称完整VM重启或24小时。

只有生命周期通过才进行一次实际控制器的**仅后端整形**确认：同一固定原生17二进制、100ms/200Mbps、30逻辑混合、四对AB/BA。入口队列保持原状。仍按原门槛：U/D逐对≥95%，两类p95逐对≤原90%且≤空载+100ms，RSS/整组CPU秒≤110%，满载两类样本各≥20、双向容量≥100Mbps、无完整性错误/OOM、清理通过。任何失败不改门槛，不借用上一阶段双端收益宣称本接入晋级，也不调参数找赢家。

Linux仅使用有界免费GitHub CI，无本地Linux测试、VPS访问或付费资源。新版默认核心选择、ARM核心渠道、真实客户端和公网三机不在本次改动；未验收项目保持NOT RUN。结果待实际CI填入。
