# 单次转发工作量优化：只做一个有界筛选

基于2522fc9继续，生产核心、参数及服务不变。问题是上游3.5.17的Direct adaptive copy在输入/输出持续Ready时没有显式每poll字节预算；复用1.6已有公平调度思路，保留上游need_flush逻辑，只增加64KiB工作量后flush并让出调度。不是限速，不改变内核缓冲、WG、认证或密码算法。

先验证现有Rust契约（部分写/背压、尾部flush、EOF/错误）和单次Ready处理量，再只编译一份候选。固定上游66708d2、参考完整补丁87a734a和已审查原生balanced1二进制cd4c5ff，Rust1.99.1、thin LTO、8 units不变。新二进制只改copy与版本号，完整参考补丁和增量补丁分别保存，禁止进入生产白名单。

只复用已有mixed_path_lab，100ms/200Mbps/MTU1420、30逻辑连接、4D+1U各16MiB，其余消息/新连接/空闲模型不改。4轮AB/BA，共8批。核心单逻辑CPU，整个实验3CPU/1536MiB/无swap/360秒；编译限制3CPU/6GiB/1500秒。无需重跑四网络条件、ARM、三KVM或旧版全矩阵。

没有收益则撤回活跃候选改动，保留该提交和全部结果供追溯；不继续铺开测试或为了绿灯调参。生产无需任何操作。
