# 旧核心 TLS 缓存运行中老化修复

2026-11-15。此分支从正式 `main` 单独创建，只带入旧核心 TLS 缓存补丁、隔离验证工具和专用 CI。正式管理器、安装器默认核心及冻结发布件未改动。先前 `security2` 的固定 SHA256 `72ab8e27f5a688264379eb76f5474ff791840615bcc06ed271f7e17afe84962d` 和验收记录仍属于旧二进制，不能套用于本次修复后的摘要。

旧候选只在启动读取磁盘文件时拒绝超过 72 小时的 profile。若进程持续运行且定期抓取失败，内存中的旧非默认 profile 会继续用于握手。修复把同一 72 小时上限用于运行中的读取、健康指标和快速重试筛选：过期时对客户端使用默认 profile，指标报告默认状态，该域会被重试；成功抓取的新 profile 重新生效。磁盘文件和内存中的旧值保留供追溯，不被原位改写。定期抓取任务睡眠中跨过过期点时，重试可能要等到下一次正常刷新唤醒；回退到默认值在读取时立即生效。

验证顺序：固定 Rust 工具链重建并运行 TLS 模拟、缓存磁盘及运行中老化定向测试；取得新 SHA 后，在私有回环网络复核合成协议、两域 TLS 源恢复、停源冷加载和真实 systemd 生命周期/回退。工作流只手动触发，限制运行时间和资源，生成的证书与密钥只在 CI 临时目录。真实 Telegram 客户端与公网验证按用户决定暂缓，不能由这些 CI 代替。
