# 满载小消息与新连接：预登记验收规则

本轮不改生产核心、WG、qdisc或sysctl。只在一次性CI网络中增加此前没有的混合体验测量，先查清满载延迟是否进入应用响应，以及发生在何处。旧版/官方17/原生17优化候选使用既有精确二进制，摘要由代码固定；不是重新编译出来的同工具链三版本对比，也不是100名真实Telegram用户。

每个profile独立免费Ubuntu22.04 runner：整个实验3逻辑CPU/1536MiB/无swap/1200秒，核心绑定一逻辑CPU；生成器+HAProxy+控制器与DC分别使用另两逻辑CPU。四个profile为0/100/200ms、200Mbps，以及100ms/100Mbps/0.1%随机丢包；MTU1420、BBR/fq、路由netem limit10000保持既有值。所有网络只在自建netns/veth/WG内。两SNI透传到同一被测后端；双后端故障交由现有独立全系统验收，不能混称本矩阵覆盖了两个后端。

每profile三轮循环换序，让三核心各占一次首、中、末；每核心依次运行30/50/100逻辑连接，中间轮反转人数顺序。人数包括：4下载+1上传（每流16MiB、SHA/ACK全验）、2个已建立连接64字节往返、4个新连接探测worker（FakeTLS+1KiB下载/ACK）、其余连接为空闲并每5秒应用保活。先测20条既有连接消息和20条新连接的空载基线，再记录文件活跃时发起的请求。每条消息验证全部64字节；不将握手客户端阶段冒充完整协议就绪。慢接收/同一连接内文件与消息复用不在本轮混合模型内。

吞吐使用实际文件起止时间；给出下载公平性、文件完成时间、应用响应和新连接p50/p95/p99、逐秒进程CPU、RSS、cgroup内存/OOM、FD回落、TCP_INFO/skmem和路由积压/丢包。p99是有限样本最近秩描述，不作稳定总体尾部分布推断。socket重传计数属于采样仍存活socket，不能冒称整个路径精确累计重传；WG软中断/内核worker开销没有完全按节点归属，进程CPU也不是整台VPS CPU。

完整性、清理、OOM先行，缺失身份/配置/顺序/资源/观测/数据时分析拒绝。任一路TCP容量对照低于带宽50%、生成端+HAProxy+控制器+探测子进程平均CPU达到70%、生成器+HAProxy或DC逐秒CPU达到70%、任一类负载期探测不足20条时，不判性能通过。另列3轮每一对旧版基线：吞吐>=95%，两类响应p95<=110%，峰值后端RSS<=110%，且负载p95相对本核心空载基线的排队增量不超过100ms。必须全部满足，不以中位数覆盖失败轮。相同核心的空载/满载关联和积压可用于定位机制，不能单独证明公网唯一根因。

工作流绿色只代表协议与分析完整执行；联合性能结论单独记录。无论是否保持，都不自动批准生产候选。样本不足、容量不足、任务失败全部保留，不事后放宽门槛。
