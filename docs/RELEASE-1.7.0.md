# 1.7.0 候选版本记录

2026-11-07。尚未发布 Release，未部署生产。目标核心是官方 3.5.16，准确 commit 与双摘要见 `telemt-stable-lock.json`。

## 改动

- 新增分离客户端、DC 与单核后端的真实 WG 长链路工具及自动证据门槛；两个独立任务确认官方 3.5.16 在 100ms 单流下载相对 balanced2 的显著退化。移植 1.6 的自动缓冲、短 RTT 接收保护和待发送限额，生成 `3.5.16+tdh.balanced1` 原生实验候选并完成长传输、并发协议、资源限制与实际维护回退验收；四流下载排队 RTT 代价尚需优化，不改变生产默认、不接入安装器。保留全部失败与 271 项回归，详见长链路报告。

- 11 月 8 日完整补验：修复后两任务三条件、30/50/100 并发共 20,160 条负载全部通过，保留初始失败；未证实相对 balanced2 的跨任务重复提速。持续传输组受生成器限制，不当作核心吞吐上限。
- 267 项 root 回归；连接维护增加 1MiB 配置/8 份备份上限，达到上限在停服务前拒绝。汇总工具拒绝缺失 CPU 数据，协议失败返回非零状态但保留 JSON。
- 三 KVM 实际验证 connect-refresh/rollback、重复操作、配置漂移时核心回退拒绝、正确顺序恢复及正常重启。准确提交和范围见本轮证据，不混称不同批次为同一个源码测试。

- 新安装默认固定官方 3.5.16，保留旧 balanced2/audit2 和官方 3.5.5 的受验证识别；管理器升级仍不隐式更换核心。
- 新增 `core-upgrade` / `core-rollback`，复用已有原子事务库，增加配置/密钥/服务快照、候选配置预检、MainPID 二进制核对和中断恢复。
- 新增入口 `backend-drain` / `backend-resume`、后端 `recover`、健康代理 `health-refresh` / `health-rollback`。
- 11 月 8 日：定位新旧核心弱网 DC 连接默认 3 秒总预算耗尽；新增每次 4 秒、最多两次、总预算 9 秒的显式配置，以及 `connect-refresh` / `connect-rollback` 私有备份、权限保持和失败恢复事务。确定性 SYN 延迟反例与 2400 条弱网负载复验通过；不宣称整体提速。
- DC 全部可达改为多数票，加入分层端口检查、失败/恢复阈值、冷却及失效时间。
- 补强状态文件/旧核心校验顺序和文件权限边界，关闭 HTTPError 资源，限制 HTTPS 重定向，保留既有脚本 LF 规则并补齐新 CI/证据属性。
- 新安装队列最低值回到与 listener 对齐的 4096，保留已有更高用户设置；不改既有节点 sysctl。
- 修复新版配置安全读取与旧 0710 父目录不兼容：新安装为 root:telemt 0750，旧节点在核心维护事务中备份、迁移及回退目录访问，不改配置内容、Secret 或密钥权限。
- 增加真实二进制、systemd、双 WG、丢包/抖动和 30/50/100 原生协议验收工具及 Ubuntu 22.04 分支及手动 CI；更新中文安装、迁移、架构和排错说明。

## 兼容与边界

继续 schema 5 / 节点协议 1.2.1。核心替换保持用户配置字节，单独连接维护仅迁移三个默认参数；保持 Secret、SNI、双线路链接和生产 TCP 透传。没有启用 WEB，没有给生产增加 Docker 或公网 API。

核心重启会影响该后端已有 TCP 会话，需逐后端排空维护。原生 ARM64、三个 Ubuntu 22.04 KVM 客体的安装/重复安装/维护/正常重启，以及 900 次有界连接资源检查已补验。官方客户端、三台物理 VPS 公网跨区和 24 小时稳定仍未验证。精确结果与失败历史见 [工程报告](ENGINEERING-REPORT-1.7.md)，不能把合成协议负载结果写成真实 Telegram 下载速度。

Ubuntu 22.04.5 有界 CI 已通过：实际核心安装/升级/回退、非特权健康代理、30/50/100 并发和丢包/抖动双 WG 恢复。首轮测试工具的 runner 目录访问失败及修正结果均保留，见工程报告。
