# 上行容量限制的单变量定位

## 执行前固定的假设和边界

此前100ms/200Mbps实验的容量对照反复为上行约69Mbps、下行约183Mbps。容量门槛仍是双向至少100Mbps；旧批次不改判，不重跑三核心大矩阵。

先区分iperf内部限速和网络本身。只在免费Ubuntu22.04标准CI、已有三命名空间和真实WireGuard上，固定100ms RTT、200Mbps双向netem、MTU1420、BBR、fq、CPU亲和性和系统默认缓冲。只改变iperf `-b200M` / `-b0`，上行ABBA、下行BAAB，各两次，共八次。每次2秒预热加6秒计量；总运行限180秒、3CPU、1.5GiB、零swap。约1.6GB以内的负载留在私有虚拟链路，不经过用户本地宽带。

保留完整iperf JSON、每秒两端TCP/socket内存及路由器队列快照，检查窗口、拥塞、重传与CPU。无Telemt编译，无核心、宿主sysctl或生产参数修改。工具完成不等于性能验收通过。

只有同方向两轮均显示取消内部限速消除容量不足，才认为该变量有因果证据；否则不采用。无论结果如何，不降低吞吐/延迟/样本门槛，不把旧失败改为通过。下一步只围绕观测到的限制处理，不扩大矩阵。
