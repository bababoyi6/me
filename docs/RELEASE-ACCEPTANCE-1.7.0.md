## 发行内容与优先级

1. x86 继续已发布、双摘要锁定的 balanced2。官方 3.5.17 是兼容目标与显式维护选项；ARM 默认官方 17。没有重新构建或改写核心数据路径，不宣称 1.7 相对同核心 1.6 新增吞吐收益。
2. 复用已完成的健康多数票、滞回、监测进度保护、原子发布及事务回退修复。Secret/SNI/链接保持，核心更换需逐后端维护。
3. 入口菜单 10 复用既有排空/恢复检查，后端菜单 8 与入口菜单 10 提供管理器回退；真实终端读取，默认返回，明确确认才执行。
4. HAProxy 部分状态变更失败明确提示逐线路检查重试；只输出固定信息，不回显原始响应。
5. README 从候选与历史实验叙述收敛到正式安装、四步配对、恢复与维护；固定标签和脚本 SHA256，保留历史安装来源。官方核心三 KVM 工具显式选择 official，修正默认恢复 balanced2 后实验身份不匹配的问题；不会将官方测试冒充默认渠道测试。

## 性能与未验证边界

本次网络预算、WireGuard/HAProxy/Telemt 数据路径及服务模板保持。相对 1.6 的 balanced2 核心为同一二进制，不能凭版本号宣布变快。官方 17 高 RTT 单流退化已知，未作为 x86 默认。满载排队问题仍存在；64KiB 调度和共享 IFB 未满足吞吐/延迟联合门槛，均已撤回。默认关闭的后端队列仍只供显式实验，不推荐生产开启。

NOT RUN：真实 Telegram 客户端全平台、公网三 VPS 跨地区/跨运营商、1Gbps 容量、24 小时长期稳定、抗封锁或抗识别效果。用户已从本次发布门槛中排除前述客户端与长期补验；发行仍不得宣称这些能力已通过。ARM 官方路径已做有限功能验证，ARM 基线切换明确拒绝。

本次放行定位：保留成熟基线的管理器、安全与恢复升级，可按文档进行保留配置的逐台部署/维护；不等于全场景性能或长期稳定认证。没有访问生产节点、过期测试 VPS，没有新付费资源。
