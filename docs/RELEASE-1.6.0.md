# 1.6.0 新装默认核心交付准备

状态：开发分支待验收及发布批准。main当前仍为1.5.0/audit2；先让配套核心资产公开可下载并核对摘要，再合并新的默认安装器，避免新安装引用不存在的文件。没有发布正式Release，没有访问或更新美国生产节点。

## 本次交付

- x86_64新安装默认使用`3.5.5+tdh.balanced2`，复用已通过CI和荷兰受控实验的同一二进制，不重新编译或更换压缩归档字节。
- 同一安装器支持明确选择`TDH_NEW_INSTALL_CORE=audit2`进行新装，下载旧的已发布归档并校验原摘要；下载或校验失败直接停止，不自动换核心。
- 新管理器同时识别摘要与版本一致的audit2和balanced2。已有节点执行`a update`或重复安装管理器时，不升级或重启核心，不重写链接/状态/配置。
- ARM仍使用原官方核心，不下载x86_64候选；显式指定仅适用于x86_64的核心选择时拒绝执行。

## 放行依据及限制

32流两轮受控对照在明确80%软节流设置下均达到预设95%门槛，128条上传完整；第二轮95.016%贴线，不宣称稳定提速。100ms入口、真实HAProxy/WG+PSK、双SNI/双方向、两后端及主备恢复的功能CI通过。安装模块真实降权新装、损坏包和已有核心拒绝、许可保留CI通过。全部成功与失败记录见[候选结果](UPLOAD-CANDIDATES-20261024.md)及[安装/路径验收](CANDIDATE-PATH-20261024.md)。

本阶段再用未修改的生产安装函数验证默认balanced2、显式audit2新装、坏包拒绝及已有文件保护；仅下载边界提供已核验归档，不能标成从已发布balanced2 URL下载。使用实际安装后的两个核心，在临时CI中各做双SNI双向8MiB持久连接、2MiB慢读和大流期间的小消息探测。总有效载荷硬限72MiB、单流进行、不做32流、CPU60%、动态MemoryMax、75%软节流、Swap0及180秒上限。该批检查正确性和背压，不用其单次时长声称吞吐提高，结果待追加。

首次源码CI发现帮助页硬编码旧版本号；改为读取同一个版本常量，避免未来再次漏改。首次交付CI在降权版本检查阶段停止：测试夹具的0755目录创建被077 umask收紧为0700，导致服务账户无法遍历；修正仅放开含公共二进制的测试父目录，生产私有目录和密钥权限不变。没有启动大流。原始失败日志保存在[交付证据目录](benchmarks/core-delivery-20261024/)，后续安装阶段失败也会保存状态报告。

这些证据支持受控的新装交付决策，不证明长期生产稳定性、30–100人实际容量、真实客户端文件速度或抗封锁效果。荷兰机上一轮观测接线失败仍保留，没有通过本阶段授权重新运行VPS。生产节点保持禁止访问。

## 退路与维护范围

发布前失败：不改main，不发布资产；现有一键命令继续下载audit2。

新装下载/身份/许可/运行校验失败：停止并按既有安装事务清理，不能遗留半安装核心或默默降级。显式audit2新装只影响本次新建节点；有项目文件时继续拒绝覆盖。

发现新默认的交付问题：可回退main的安装器选择，恢复未来新装使用audit2；已部署节点不会被远程自动改写。已有服务要更换核心必须另行安排维护、保留二进制与配置并确认同伴健康。本版本没有新增自动滚动升级或公开核心切换命令，不能把安装前选择称为已运行服务无中断回退。

## 发布顺序

1. 完成源码CI、实际安装/拒绝检查和有界大文件正确性CI，保存原始证据。
2. 准备可审阅的草稿资产、源码及SHA256清单，取得原任务要求的发布授权。
3. 发布配套核心资产，重新从公开URL下载并核对归档及内含二进制摘要。
4. 仅在资产确实可用后合并1.6.0默认安装器；检查main的CI。现有节点管理器维护和新装核心选择保持分离。
