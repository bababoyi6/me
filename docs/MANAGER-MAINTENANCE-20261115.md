# 管理器维护分支

2026-11-15。从正式 `main` 的 v1.7.1 基础创建 `dev/20261115-manager-maintenance`，只整理管理器入口、入口配置迁移、后端恢复、只读性能诊断与对应测试。该分支不包含实验核心构建补丁、性能矩阵或候选核心安装路径。正式安装脚本与下载摘要仍指向已发布的 v1.7.1。

- 入口将两条路由共用的健康状态交给独立 `telemt_health` 后端；仅接受健康代理的 `up` 行。旧入口可用 `a entry-health-refresh` 迁移，失败自动尝试恢复；`a entry-health-rollback` 保留人工回退路径。
- `a recover` 只启动缺失服务并等待健康代理就绪；显式 `--restart` 才重启后端服务。脚本会提示已有连接可能断开。
- `a perf` 增加 cgroup CPU 配额、节流增量及本机 PSI 读数，仍是只读采样。
- 工作分支脚本不同于 README 固定的发布脚本；测试分别核对正式下载摘要与当前工作脚本，不将未发布字节冒充已发布资产。

本地 Windows 已通过入口维护和发布锁的纯 Python 回归。HAProxy 实际重载、Bash/ShellCheck、管理器生命周期和完整性能诊断回归由手动触发、12 分钟上限的 Ubuntu 22.04 CI 检查。本分支验证通过也不等于已发布或部署；部署窗口和真实流量仍需要单独决定。
