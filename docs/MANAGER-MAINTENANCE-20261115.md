# 管理器维护分支

2026-11-15 从正式 `main` 的 v1.7.1 基础创建 `dev/20261115-manager-maintenance`；2026-11-16 已合入当时最新 `main` 以复核兼容性。PR 相对 `main` 的改动只涉及管理器入口、入口配置迁移、后端恢复、只读性能诊断与对应测试，不改候选核心安装路径。正式安装脚本与下载摘要仍指向已发布的 v1.7.1。

- 入口将两条路由共用的健康状态交给独立 `telemt_health` 后端；仅接受健康代理的 `up` 行。旧入口可用 `a entry-health-refresh` 迁移，失败自动尝试恢复；`a entry-health-rollback` 保留人工回退路径。
- `a recover` 只启动缺失服务并等待健康代理就绪；显式 `--restart` 才重启后端服务。脚本会提示已有连接可能断开。
- `a perf` 增加 cgroup CPU 配额、节流增量及本机 PSI 读数，仍是只读采样。
- 工作分支脚本不同于 README 固定的发布脚本；测试分别核对正式下载摘要与当前工作脚本，不将未发布字节冒充已发布资产。

本地 Windows 已通过入口维护和发布锁的纯 Python 回归。HAProxy 实际重载、Bash/ShellCheck、管理器生命周期和完整性能诊断回归由本分支推送触发、12 分钟上限的 Ubuntu 22.04 CI 检查。本分支验证通过也不等于已发布或部署；部署窗口和真实流量仍需要单独决定。

首次分支 [CI 43688596483](https://github.com/bababoyi6/me/actions/runs/43688596483) 的 Bash、ShellCheck、发布锁、入口迁移和管理器生命周期通过。完整诊断回归仅在旧模板哈希锁失败：共享 HAProxy 健康模板是本分支有意修改的函数。测试现单独固定其新 SHA256，其余运行模板继续按原始基线摘要验证；重跑结果另行记录。

[CI 43688835733](https://github.com/bababoyi6/me/actions/runs/43688835733) 复验全部专项步骤通过。2026-11-16 审查发现，原子替换入口配置后若目录同步报错，恢复处理还未开始，可能留下磁盘配置与运行配置不一致。现将配置发布纳入同一自动恢复异常路径，并增加“替换完成后报错”的 HAProxy 故障注入。首次新 [CI 43788732402](https://github.com/bababoyi6/me/actions/runs/43788732402) 在注入前遇到上一个重载的健康检查尚未转为 UP，安全前置条件拒绝操作；测试等待就绪后，[CI 43788870216](https://github.com/bababoyi6/me/actions/runs/43788870216) 在最新 `main` 基线上通过 Bash、ShellCheck、发行锁、HAProxy 迁移与恢复、管理器生命周期及诊断。此结果只支持代码审查，不代表已发布或部署。
